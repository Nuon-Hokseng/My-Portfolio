## Motion stability correction

- User feedback exposed a gap in the earlier checks: advancing transforms and a good frame interval do not establish comfortable motion. Reproduced a fully revealed skill card dropping from opacity `1` back to `0` on a revisit. The replay/reset logic and very front-loaded easing made scrolling feel jumpy.
- Removed the replay/rearm observer. Each element now reveals once per visit and stays visible afterward, even during quick direction changes. Offscreen elements receive their starting state before entry, rather than appearing first and then being hidden by the observer callback. Already-visible content, direct section links, and visible gallery replacements skip the entrance entirely.
- Unified entrances at **1100ms**, with a gentler `cubic-bezier(.25,.46,.45,.94)` curve and short **60ms** stagger capped at **120ms**. Reduced travel to 14-30px on desktop (less on narrow screens), removed card/text rotations and strong scaling, and softened hover lifts and timeline accents. The small hero title entrance is now 900ms with the same easing.
- Reduced-motion changes and backgrounding settle content without restarting it. Keyboard focus also settles moving controls immediately. The centered project modal, native scrolling, layout, and touch portrait behavior are preserved.
- Reworked `test:motion` to check actual frame-by-frame opacity monotonicity, pre-entry preparation, one actual animation start despite repeated scroll reversals/revisits, dynamic gallery replacements, direct section links, keyboard focus, and reduced motion. Android-emulation stability is also exercised with 4x CPU slowdown. These are browser regressions, not a guarantee of a particular frame rate or physical-device testing.
- Local lint, TypeScript, production build, all 22 entrance samples, direction-reversal/revisit regressions and the 10 viewport/theme UI matrix passed. The UI matrix retained zero browser errors and zero automated axe violations. A direct-link regression found during testing was fixed by keeping the initial destination section fully visible, even if native anchor scrolling occurs after hydration.
